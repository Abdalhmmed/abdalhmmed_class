1. مدخل التعقيد: ما هو رمز Big-O وكيف نقيس كفاءة الكود؟

ما هو رمز Big-O وما هو اختصار له؟
الحرف O هو اختصار لكلمة "Order of Growth" (رتبة أو وتيرة نمو العمليات). هو لغة ومقياس رياضي عالمي موحد يجيب عن السؤال الجوهري: «إذا زاد حجم البيانات المدخلة للبرنامج (n)، فبأي وتيرة ومعدل سيزداد عدد العمليات والخطوات التي ينفذها المعالج؟»

لماذا لا نقيس الكفاءة بالثواني؟

لأن الثواني مقياس خادع يعتمد على سرعة المعالج، نوع نظام التشغيل، وحجم الذاكرة. نفس الكود قد يستغرق 0.05 ثانية على حاسوب متطور و 4 ثوانٍ على جهاز بطيء.

لماذا نستخدم رمز Big-O؟

لأنه يقيس الخطوات والعمليات المنطقية المستقلة عن العتاد، ويعطينا تقييماً ثابتاً وموضوعياً لجودة الفكرة التصميمية للخوارزمية.

ماذا يمثل الحرف (n)؟

n يمثل حجم المدخلات (عدد العناصر). في المصفوفات: إذا كانت المصفوفة تحتوي على 5 عناصر فإن n = 5، وإذا كانت 1000 عنصر فإن n = 1000.

ماذا نعدّ بالضبط داخل الكود لحساب التعقيد؟

المقارنات (Comparisons)

شروط الحلقات i < n وفحص if.

القراءات (Reads)

الوصول لقيمة من خانة المصفوفة arr[i].

الكتابات (Writes)

تخزين وإسناد في متغير أو خانة arr[i] = x.

المجموع الكلي

مجموع العمليات ومنه نستخرج رتبة النمو.

رُتب Big-O الأساسية مرتبة من الأسرع إلى الأبطأ:

الرمز الاسم العلمي الوصف وسلوك النمو مثال من المصفوفات
O(1) ثابت (Constant) خطوة واحدة ثابتة لا تتأثر بحجم البيانات نهائياً. الوصول للخانة بالفهرس arr[i]
O(log n) لوغاريتمي (Logarithmic) فائق السرعة؛ تُقسم مساحة البحث إلى النصف في كل خطوة. البحث الثنائي في مصفوفة مرتبة
O(n) خطي (Linear) يتناسب طردياً مع n؛ إذا تضاعف n يتضاعف العمل. المرور بحلقة واحدة لحساب المجموع
O(n²) تربيعي (Quadratic) حلقتان متداخلتان؛ إذا تضاعف n يتضاعف العمل 4 مرات. الترتيب الفقاعي (Bubble Sort)

الحالات الثلاث لتقييم أداء الخوارزمية (Cases of Analysis):

الحالة المفهوم العلمي مثال من البحث الخطي
أفضل حالة (Best Case) أسهل سيناريو للمدخلات؛ أقل عدد ممكن من الخطوات. العنصر المطلوب يقع في أول خانة arr[0] مباشرة.
الحالة المتوسطة (Average Case) الأداء المتوقع عند تشغيل البرنامج على بيانات عشوائية. العنصر في منتصف المصفوفة تقريباً (n/2).
أسوأ حالة (Worst Case) أصعب سيناريو ممكن؛ أعلى سقف للعمليات (Upper Bound). العنصر المطلوب في آخر خانة أو غير موجود إطلاقاً (n).

2. ماهية المصفوفة (المفهوم، التصميم، والذاكرة)

2.1 مشكلة المتغيرات المنفصلة وحلها بالمصفوفة

بدون مصفوفة (كابوس برمجي)

int mark1 = 85; int mark2 = 92; int mark3 = 78; int mark4 = 64; int mark5 = 90; // لحساب المجموع: int sum = mark1 + mark2 + mark3 + mark4 + mark5;

متغيرات متفرقة، لا يمكن المرور عليها بحلقة، والكود يزداد تعقيداً مع كل عنصر إضافي.

مع مصفوفة (الحل الذكي والمنظم)

int[] marks = {85, 92, 78, 64, 90}; int sum = 0; for (int i = 0; i < marks.length; i++) { sum += marks[i]; }

اسم واحد جامع، وحلقة واحدة من سطرين تجمع درجات 5 طلاب أو حتى مليون طالب.

تعريف المصفوفة (Array): بنية بيانات خطية متجانسة تخزن مجموعة عناصر من نفس النوع في مواقع متجاورة ومتلاصقة تماماً في الذاكرة تحت اسم واحد، ونصل لكل عنصر عبر رقم موقعه (الفهرس Index) الذي يبدأ دائماً من 0.

2.2 هيكل المصفوفة في الذاكرة ولماذا يبدأ الفهرس من 0؟

المعالج يعرف عنوان أول خانة فقط في الذاكرة (Base Address). ولأن جميع الخانات متطابقة في الحجم ومحجوزة على التوالي، فإن الفهرس (Index) يمثل في الأصل مقدار الإزاحة (Offset) عن نقطة البداية وفق المعادلة الفيزيائية:

المعادلة: العنوان الفيزيائي للخانة = Base Address + (Index × حجم نوع البيانات)

النتيجة الهندسية: لأن المعالج ينفذ عملية الضرب والجمع في دورة ساعة واحدة، فإن الوصول وقراءة أي عنصر في المصفوفة يستغرق دائماً زمناً ثابتاً O(1) مهما بلغ طول المصفوفة!

2.3 مراحل حياة المصفوفة في Java

المرحلة 1

1. التصريح (Declaration)

int[] marks;

نعلن فقط عن اسم سيكون مصفوفة. لم تُحجز أي خانات بعد في الذاكرة (قيمته null).

المرحلة 2

2. الحجز بواسطة new

marks = new int[5];

تُحجز 5 خانات متتالية في الـ Heap فوراً، وتأخذ قيماً افتراضية تلقائية (0 للأعداد).

المرحلة 3

3. التعبئة (Initialization)

marks[0] = 85;

نضع القيم الحقيقية في الخانات بالفهرس، أو ندمج المراحل الثلاث بسطر واحد جاهز.

2.4 المرور على العناصر بحلقة for التقليدية بالفهرس

for (int i = 0; i < marks.length; i++) { System.out.println("marks[" + i + "] = " + marks[i]); marks[i] += 5; // يمكننا التعديل على الخانة في مكانها لأننا نملك الفهرس i! }

قاعدة هامة: يبدأ العداد i من 0 ويزداد بمقدار 1 حتى يصل إلى marks.length - 1. نستخدم دائماً i < marks.length لتجنب خطأ تجاوز الحدود (ArrayIndexOutOfBoundsException).

3. العمليات الأساسية على المصفوفات (تحليل وتطبيق)

3.1 الوصول والتعديل المباشر (Direct Access & Update) التعقيد الزمني: O(1) · المكاني: O(1)

الوصول لقيمة أي عنصر أو تعديلها يتم فوراً عبر حسابه الفيزيائي المباشر دون المرور على ما قبله.

int x = arr[2]; // قراءة العنصر في الفهرس 2 بتعقيد O(1) arr[2] = 88; // تعديل القيمة في خطوة واحدة ثابتة O(1)
3.2 المرور وحساب المجموع والمتوسط (Sum & Average) التعقيد الزمني: O(n) · المكاني: O(1)

نستخدم متغيراً مجمعاً sum = 0، ثم نمر بحلقة واحدة على جميع العناصر ونجمعها، وفي النهاية نقسم على arr.length.

int sum = 0; for (int i = 0; i < arr.length; i++) { sum += arr[i]; } double avg = (double) sum / arr.length;
3.3 البحث الخطي (Linear Search) أفضل حالة: O(1) · أسوأ حالة: O(n)

نفحص العناصر عنصراً تلو الآخر من البداية حتى نجد القيمة المطلوبة فنخرج فوراً بـ break، أو تنتهي المصفوفة فنرجع -1.

int target = 25, foundIndex = -1; for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { foundIndex = i; break; // وجدنا القيمة، نخرج فوراً } }
أفضل حالة (Best Case): O(1)
عندما يكون العنصر في الخانة الأولى arr[0].
أسوأ حالة (Worst Case): O(n)
عندما يكون العنصر في آخر خانة أو غير موجود إطلاقاً.
3.4 إيجاد أكبر وأصغر قيمة (Min & Max) التعقيد الزمني: O(n) · المكاني: O(1)

نفترض أن أول عنصر arr[0] هو الأكبر والأصغر مبدئياً، ثم نمر في حلقة واحدة من الفهرس 1 لتحديثهما:

int max = arr[0], min = arr[0]; for (int i = 1; i < arr.length; i++) { if (arr[i] > max) max = arr[i]; if (arr[i] < min) min = arr[i]; }
3.5 عكس المصفوفة مكانياً (In-Place Reverse) المكاني: O(1) · الزمني: O(n)

نستخدم مؤشرين (Two Pointers): left = 0 و right = length - 1 ونبدل بينهما بمتغير وسيط temp دون إنشاء مصفوفة ثانية:

int left = 0, right = arr.length - 1; while (left < right) { int temp = arr[left]; arr[left] = arr[right]; arr[right] = temp; left++; right--; }

4. العمليات الهيكلية: الإضافة والحذف بالتفصيل

لماذا الإضافة والحذف يتطلبان O(n) زمناً ومكاناً في مصفوفات Java؟
لأن حجم المصفوفة ثابت تماماً (Fixed Size) في الذاكرة الفيزيائية. لا يمكن توسيع الخانات في مكانها ولا تقليصها، لذا لا بد من: حجز مصفوفة جديدة بالكامل ونقل العناصر إليها مع إزاحة المواقع.
4.1 عملية الإضافة في موقع محدد (Insertion at Position) التعقيد الزمني: O(n) · المكاني: O(n)

تتم الإضافة وفق 3 مراحل واضحة:

  1. المرحلة 1 (النسخ المباشر): حجز مصفوفة جديدة بحجم result[n + 1] ونسخ العناصر السابقة لموقع الإضافة (من الفهرس 0 إلى pos-1) كما هي.
  2. المرحلة 2 (غرس العنصر الجديد): وضع القيمة الجديدة في موقعها المخصص: result[pos] = val;
  3. المرحلة 3 (الإزاحة لليمين): نسخ ما تبقى من العناصر ونقل كل عنصر إلى result[i + 1] (إزاحة خانة واحدة لليمين).
مخطط إزاحة الذاكرة أثناء الإضافة:

[0]
99 (جديد)
[1] (pos)
20 (مُزاح)
[2]
30 (مُزاح)
[3]
40 (مُزاح)
[4]
public static int[] insert(int[] arr, int pos, int val) { // 1. حجز مصفوفة جديدة أطول بخانة واحدة int[] result = new int[arr.length + 1]; // 2. نسخ العناصر السابقة لموقع الإضافة كما هي for (int i = 0; i < pos; i++) { result[i] = arr[i]; } // 3. وضع القيمة الجديدة في مكانها المخصص result[pos] = val; // 4. نسخ العناصر اللاحقة مع إزاحتها لليمين (+1) for (int i = pos; i < arr.length; i++) { result[i + 1] = arr[i]; } return result; // إرجاع المصفوفة الجديدة }
4.2 عملية الحذف من موقع محدد (Deletion at Position) التعقيد الزمني: O(n) · المكاني: O(n)

يتم الحذف وفق 3 مراحل واضحة:

  1. المرحلة 1 (النسخ المباشر): حجز مصفوفة جديدة بحجم result[n - 1] ونسخ العناصر السابقة لموقع الحذف (من 0 إلى pos-1) كما هي.
  2. المرحلة 2 (التخطي): تخطي العنصر المحذوف arr[pos] تماماً وعدم نسخه للمصفوفة الجديدة.
  3. المرحلة 3 (الإزاحة لليسار): نسخ بقية العناصر ونقل كل منها إلى result[i - 1] لملء الفراغ.
مخطط سحب العناصر لملء الفراغ أثناء الحذف:

[0]
20
[1]
30 (حُذف)
[2] (pos)
40 ← يسار
[2] بدلاً من [3]
50 ← يسار
[3] بدلاً من [4]
public static int[] delete(int[] arr, int pos) { // 1. حجز مصفوفة جديدة أصغر بخانة واحدة int[] result = new int[arr.length - 1]; // 2. نسخ العناصر السابقة لموقع الحذف كما هي for (int i = 0; i < pos; i++) { result[i] = arr[i]; } // 3. نسخ العناصر اللاحقة مع إزاحتها لليسار خانة (-1) لملء الفراغ for (int i = pos + 1; i < arr.length; i++) { result[i - 1] = arr[i]; } return result; // إرجاع المصفوفة بعد الحذف }

5. مرجع الأكواد الأساسية الجاهزة (CRUD Operations)

برنامج Java متكامل يجمع الدوال الأربع الرئيسية (إضافة، تعديل، حذف، بحث) مع دالة main توضح كيفية استدعائها بالتسلسل:

/** * مختبر هياكل البيانات والخوارزميات (Data Structures Lab) * إعداد وتطوير: م. عبدالحميد هلال دعبان (بكالوريوس علوم حاسوب) * موضوع المعمل: العمليات الأساسية على المصفوفات الأحادية (Array CRUD & Analysis) */ public class ArrayCRUD { // 1. الإضافة: حجز مصفوفة جديدة وإزاحة العناصر لليمين O(n) public static int[] insert(int[] arr, int pos, int val) { int[] res = new int[arr.length + 1]; for (int i = 0; i < pos; i++) { res[i] = arr[i]; } res[pos] = val; for (int i = pos; i < arr.length; i++) { res[i + 1] = arr[i]; } return res; } // 2. التعديل: وصول مباشر وتغيير القيمة في خطوة واحدة O(1) public static void update(int[] arr, int index, int newVal) { if (index >= 0 && index < arr.length) { arr[index] = newVal; } } // 3. الحذف: حجز مصفوفة جديدة وإزاحة العناصر لليسار O(n) public static int[] delete(int[] arr, int pos) { int[] res = new int[arr.length - 1]; for (int i = 0; i < pos; i++) { res[i] = arr[i]; } for (int i = pos + 1; i < arr.length; i++) { res[i - 1] = arr[i]; } return res; } // 4. البحث: مقارنة تسلسلية خطوة بخطوة O(n) public static int search(int[] arr, int target) { for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { return i; } } return -1; } // برنامج تجريبي لتشغيل العمليات: public static void main(String[] args) { int[] arr = {10, 20, 30, 40}; // أ. إضافة 99 في الموقع 1: arr = insert(arr, 1, 99); // النتيجة: {10, 99, 20, 30, 40} // ب. تعديل العنصر في الفهرس 0: update(arr, 0, 55); // النتيجة: {55, 99, 20, 30, 40} // ج. حذف العنصر في الموقع 2: arr = delete(arr, 2); // النتيجة: {55, 99, 30, 40} // د. البحث عن الرقم 30: int idx = search(arr, 30); // يرجع الفهرس 2 System.out.println("الموقع: " + idx); } }
