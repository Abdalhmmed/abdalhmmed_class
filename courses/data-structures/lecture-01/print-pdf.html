1. Introduction to Complexity: What is Big-O & How We Measure Code?

What does Big-O stand for?
The letter O stands for "Order of Growth". It is a universal mathematical notation that answers a fundamental engineering question: "As the input size (n) grows larger, at what rate does the number of CPU operations scale?"

Why not measure in seconds?

Wall-clock seconds are hardware-dependent. The exact same program might take 0.05s on a workstation and 4.0s on an older laptop or busy operating system.

Why use Big-O Notation?

Big-O counts logical elementary operations independently of hardware, giving an objective, machine-agnostic measure of an algorithm's design quality.

What does (n) represent?

n represents the input size (number of elements). In an array of 5 elements, n = 5; in an array of 1,000 elements, n = 1000.

What Elementary Operations Do We Count Inside Code?

Comparisons

Loop conditions i < n and if checks.

Memory Reads

Fetching an element value arr[i] from RAM.

Memory Writes

Assigning or storing a value arr[i] = x.

Σ

Total Cost

Sum of operations from which we extract the Big-O class.

Common Big-O Complexity Classes (Fastest to Slowest):

Notation Complexity Name Growth Behavior Array Example
O(1) Constant Time Executes in a fixed number of steps regardless of how large n grows. Direct index access arr[i]
O(log n) Logarithmic Time Extremely fast; cuts the remaining search space in half at each step. Binary Search on a sorted array
O(n) Linear Time Grows proportionally with n; doubling n doubles the number of steps. Single loop traversal / Sum
O(n²) Quadratic Time Nested loops over n; doubling n quadruples (4×) the total work. Bubble Sort / All-pairs check

The Three Cases of Algorithmic Analysis:

Analysis Case Scientific Definition Linear Search Example
Best Case Most favorable input configuration requiring the minimum possible steps. Target value is found immediately at arr[0].
Average Case Expected performance across typical random input distributions. Target value is found near the middle (approx. n/2 steps).
Worst Case Most demanding input configuration; guarantees an upper bound on runtime. Target is at the very last index or not present at all (n steps).

2. Array Architecture (Concept, Memory Layout & Lifecycle)

2.1 The Separate Variables Problem vs. The Array Solution

Without an Array (Unscalable)

int mark1 = 85; int mark2 = 92; int mark3 = 78; int mark4 = 64; int mark5 = 90; // Computing total sum manually: int sum = mark1 + mark2 + mark3 + mark4 + mark5;

Scattered variables cannot be traversed with a loop; scaling to 1,000 students is practically impossible.

With an Array (Clean & Scalable)

int[] marks = {85, 92, 78, 64, 90}; int sum = 0; for (int i = 0; i < marks.length; i++) { sum += marks[i]; }

A single unified identifier and a 3-line loop seamlessly process 5 or 1,000,000 elements.

Array Definition: A homogeneous, linear data structure that stores a fixed-size sequence of elements of the exact same data type in strictly contiguous (back-to-back) memory locations under one name, accessed via a zero-based Index.

2.2 Physical Memory Layout & Why Array Indexing Starts at 0

The CPU only stores the memory address of the very first slot (the Base Address). Because every element has the exact same byte size and sits back-to-back in RAM, the index is actually a distance offset from the Base Address:

Physical Address Formula: Address(i) = Base_Address + (i × Element_Size_in_Bytes)

Each int occupies 4 bytes. The first element has an offset of 0 (Base + 0 × 4 = Base), which is why indexing starts at 0.
Architectural Takeaway: Because the CPU evaluates Base + i × 4 in a single arithmetic instruction, reading or writing any array element takes constant time O(1) regardless of array length!

2.3 Array Lifecycle in Java

Stage 1

1. Declaration

int[] marks;

Creates a reference variable on the Stack. No contiguous slots are allocated yet (points to null).

Stage 2

2. Heap Allocation (new)

marks = new int[5];

Reserves 5 contiguous slots in Heap memory and automatically zero-initializes them (0 for numeric types).

Stage 3

3. Initialization

marks[0] = 85;

Populates slots by index, or combines all 3 stages in one literal line: int[] a = {85, 92};

2.4 Traversing Elements Using a Standard Indexed for-Loop

for (int i = 0; i < marks.length; i++) { System.out.println("marks[" + i + "] = " + marks[i]); marks[i] += 5; // In-place modification is possible because we have the index i }

Golden Rule: Counter i starts at 0 and runs while i < marks.length (stopping at length - 1) to prevent ArrayIndexOutOfBoundsException.

3. Core Array Operations (Analysis & Implementation)

3.1 Direct Access & Update by Index Time: O(1) · Space: O(1)

Reading or updating any element by its index jumps directly to its physical memory address without scanning preceding elements.

int x = arr[2]; // Read element at index 2 in O(1) constant time arr[2] = 88; // Overwrite element at index 2 in O(1) constant time
3.2 Traversal, Sum & Average Time: O(n) · Space: O(1)

Initialize an accumulator variable sum = 0, visit every element once in a single loop, and divide by arr.length.

int sum = 0; for (int i = 0; i < arr.length; i++) { sum += arr[i]; } double avg = (double) sum / arr.length;
3.3 Linear Search (Sequential Scan) Best: O(1) · Worst: O(n)

Inspect elements sequentially from index 0. Return or break immediately upon finding target, or return -1 if not found.

int target = 25, foundIndex = -1; for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { foundIndex = i; break; // Target found; exit loop early } }
Best Case: O(1)
Target element is located at the first slot arr[0].
Worst Case: O(n)
Target element is at the last slot or absent from the array.
3.4 Finding Minimum & Maximum Values (Min & Max) Time: O(n) · Space: O(1)

Assume the first element arr[0] is both the initial minimum and maximum, then scan from index 1 to n - 1:

int max = arr[0], min = arr[0]; for (int i = 1; i < arr.length; i++) { if (arr[i] > max) max = arr[i]; if (arr[i] < min) min = arr[i]; }
3.5 In-Place Array Reversal (Two-Pointers) Space: O(1) · Time: O(n)

Place two pointers at opposite ends (left = 0, right = length - 1) and swap pairs inward using a temporary variable temp in n/2 steps without allocating a second array:

int left = 0, right = arr.length - 1; while (left < right) { int temp = arr[left]; arr[left] = arr[right]; arr[right] = temp; left++; right--; }

4. Structural Operations: Insertion & Deletion in Detail

Why do Insertion and Deletion require O(n) Time and O(n) Space in Java Arrays?
Because standard Java arrays have a strictly fixed capacity in contiguous RAM. You cannot stretch or shrink an allocated block in place; therefore, you must allocate a brand-new array and copy/shift elements across.
4.1 Insertion at a Specific Position Time: O(n) · Space: O(n)

Insertion executes in 3 structured stages:

  1. Stage 1 (Prefix Copy): Allocate a new array result[n + 1] and copy elements before pos (indices 0 to pos - 1) unchanged.
  2. Stage 2 (Plant New Value): Store the new element at the target index: result[pos] = val;
  3. Stage 3 (Shift Right): Copy remaining elements from pos to n - 1 into result[i + 1] (shifted 1 slot right).

public static int[] insert(int[] arr, int pos, int val) { // 1. Allocate a new array larger by 1 slot int[] result = new int[arr.length + 1]; // 2. Copy elements before 'pos' as-is for (int i = 0; i < pos; i++) { result[i] = arr[i]; } // 3. Insert the new value at 'pos' result[pos] = val; // 4. Copy remaining elements shifted 1 position to the right (i + 1) for (int i = pos; i < arr.length; i++) { result[i + 1] = arr[i]; } return result; }
4.2 Deletion at a Specific Position Time: O(n) · Space: O(n)

Deletion executes in 3 structured stages:

  1. Stage 1 (Prefix Copy): Allocate a smaller array result[n - 1] and copy elements before pos (indices 0 to pos - 1) unchanged.
  2. Stage 2 (Skip Target): Bypass the element at arr[pos] so it is excluded from the new array.
  3. Stage 3 (Shift Left): Copy elements after pos (from pos + 1 to n - 1) into result[i - 1] to close the gap.

public static int[] delete(int[] arr, int pos) { // 1. Allocate a new array smaller by 1 slot int[] result = new int[arr.length - 1]; // 2. Copy elements before 'pos' as-is for (int i = 0; i < pos; i++) { result[i] = arr[i]; } // 3. Copy subsequent elements shifted 1 position to the left (i - 1) for (int i = pos + 1; i < arr.length; i++) { result[i - 1] = arr[i]; } return result; }

5. Standard Java Code Reference (Complete CRUD Operations)

A complete, self-contained Java program combining all four core CRUD methods (insert, update, delete, search) with a main driver method:

/** * Data Structures & Algorithms Lab * Prepared by: Eng. Abdulhamid Helal Daban (B.Sc. in Computer Science) * Module: 1D Array CRUD Operations & Complexity Analysis */ public class ArrayCRUD { // 1. INSERT: Allocate new array & shift elements right — Time: O(n), Space: O(n) public static int[] insert(int[] arr, int pos, int val) { int[] res = new int[arr.length + 1]; for (int i = 0; i < pos; i++) { res[i] = arr[i]; } res[pos] = val; for (int i = pos; i < arr.length; i++) { res[i + 1] = arr[i]; } return res; } // 2. UPDATE: Direct index write in constant time — Time: O(1), Space: O(1) public static void update(int[] arr, int index, int newVal) { if (index >= 0 && index < arr.length) { arr[index] = newVal; } } // 3. DELETE: Allocate smaller array & shift elements left — Time: O(n), Space: O(n) public static int[] delete(int[] arr, int pos) { int[] res = new int[arr.length - 1]; for (int i = 0; i < pos; i++) { res[i] = arr[i]; } for (int i = pos + 1; i < arr.length; i++) { res[i - 1] = arr[i]; } return res; } // 4. SEARCH: Sequential linear scan — Best: O(1), Worst: O(n), Space: O(1) public static int search(int[] arr, int target) { for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { return i; } } return -1; } // Driver program demonstrating sequential CRUD execution: public static void main(String[] args) { int[] arr = {10, 20, 30, 40}; // A. Insert 99 at index 1: arr = insert(arr, 1, 99); // Result: {10, 99, 20, 30, 40} // B. Update element at index 0 to 55: update(arr, 0, 55); // Result: {55, 99, 20, 30, 40} // C. Delete element at index 2: arr = delete(arr, 2); // Result: {55, 99, 30, 40} // D. Search for value 30: int idx = search(arr, 30); // Returns index 2 System.out.println("Found at index: " + idx); } }

1. مدخل التعقيد: ما هو رمز Big-O وكيف نقيس كفاءة الكود؟

ما هو رمز Big-O وما هو اختصار له؟
الحرف O هو اختصار لكلمة "Order of Growth" (رتبة أو وتيرة نمو العمليات). هو لغة ومقياس رياضي عالمي موحد يجيب عن السؤال الجوهري: «إذا زاد حجم البيانات المدخلة للبرنامج (n)، فبأي وتيرة ومعدل سيزداد عدد العمليات والخطوات التي ينفذها المعالج؟»

لماذا لا نقيس الكفاءة بالثواني؟

لأن الثواني مقياس خادع يعتمد على سرعة المعالج، نوع نظام التشغيل، وحجم الذاكرة. نفس الكود قد يستغرق 0.05 ثانية على حاسوب متطور و 4 ثوانٍ على جهاز بطيء.

لماذا نستخدم رمز Big-O؟

لأنه يقيس الخطوات والعمليات المنطقية المستقلة عن العتاد، ويعطينا تقييماً ثابتاً وموضوعياً لجودة الفكرة التصميمية للخوارزمية.

ماذا يمثل الحرف (n)؟

n يمثل حجم المدخلات (عدد العناصر). في المصفوفات: إذا كانت المصفوفة تحتوي على 5 عناصر فإن n = 5، وإذا كانت 1000 عنصر فإن n = 1000.

ماذا نعدّ بالضبط داخل الكود لحساب التعقيد؟

المقارنات (Comparisons)

شروط الحلقات i < n وفحص if.

القراءات (Reads)

الوصول لقيمة من خانة المصفوفة arr[i].

الكتابات (Writes)

تخزين وإسناد في متغير أو خانة arr[i] = x.

Σ

المجموع الكلي

مجموع العمليات ومنه نستخرج رتبة النمو.

رُتب Big-O الأساسية مرتبة من الأسرع إلى الأبطأ:

الرمز الاسم العلمي الوصف وسلوك النمو مثال من المصفوفات
O(1) ثابت (Constant) خطوة واحدة ثابتة لا تتأثر بحجم البيانات نهائياً. الوصول للخانة بالفهرس arr[i]
O(log n) لوغاريتمي (Logarithmic) فائق السرعة؛ تُقسم مساحة البحث إلى النصف في كل خطوة. البحث الثنائي في مصفوفة مرتبة
O(n) خطي (Linear) يتناسب طردياً مع n؛ إذا تضاعف n يتضاعف العمل. المرور بحلقة واحدة لحساب المجموع
O(n²) تربيعي (Quadratic) حلقتان متداخلتان؛ إذا تضاعف n يتضاعف العمل 4 مرات. الترتيب الفقاعي (Bubble Sort)

الحالات الثلاث لتقييم أداء الخوارزمية (Cases of Analysis):

الحالة المفهوم العلمي مثال من البحث الخطي
أفضل حالة (Best Case) أسهل سيناريو للمدخلات؛ أقل عدد ممكن من الخطوات. العنصر المطلوب يقع في أول خانة arr[0] مباشرة.
الحالة المتوسطة (Average Case) الأداء المتوقع عند تشغيل البرنامج على بيانات عشوائية. العنصر في منتصف المصفوفة تقريباً (n/2).
أسوأ حالة (Worst Case) أصعب سيناريو ممكن؛ أعلى سقف للعمليات (Upper Bound). العنصر المطلوب في آخر خانة أو غير موجود إطلاقاً (n).

2. ماهية المصفوفة (المفهوم، التصميم، والذاكرة)

2.1 مشكلة المتغيرات المنفصلة وحلها بالمصفوفة

بدون مصفوفة (كابوس برمجي)

int mark1 = 85; int mark2 = 92; int mark3 = 78; int mark4 = 64; int mark5 = 90; // لحساب المجموع: int sum = mark1 + mark2 + mark3 + mark4 + mark5;

متغيرات متفرقة، لا يمكن المرور عليها بحلقة، والكود يزداد تعقيداً مع كل عنصر إضافي.

مع مصفوفة (الحل الذكي والمنظم)

int[] marks = {85, 92, 78, 64, 90}; int sum = 0; for (int i = 0; i < marks.length; i++) { sum += marks[i]; }

اسم واحد جامع، وحلقة واحدة من سطرين تجمع درجات 5 طلاب أو حتى مليون طالب.

تعريف المصفوفة (Array): بنية بيانات خطية متجانسة تخزن مجموعة عناصر من نفس النوع في مواقع متجاورة ومتلاصقة تماماً في الذاكرة تحت اسم واحد، ونصل لكل عنصر عبر رقم موقعه (الفهرس Index) الذي يبدأ دائماً من 0.

2.2 هيكل المصفوفة في الذاكرة ولماذا يبدأ الفهرس من 0؟

marks = new int[5];

2.4 المرور على العناصر بحلقة for التقليدية بالفهرس

for (int i = 0; i < marks.length; i++) { System.out.println("marks[" + i + "] = " + marks[i]); marks[i] += 5; // يمكننا التعديل على الخانة في مكانها لأننا نملك الفهرس i! }

قاعدة هامة: يبدأ العداد i من 0 ويزداد بمقدار 1 حتى يصل إلى marks.length - 1. نستخدم دائماً i < marks.length لتجنب خطأ تجاوز الحدود (ArrayIndexOutOfBoundsException).

3. العمليات الأساسية على المصفوفات (تحليل وتطبيق)

3.1 الوصول والتعديل المباشر (Direct Access & Update) التعقيد الزمني: O(1) · المكاني: O(1)

الوصول لقيمة أي عنصر أو تعديلها يتم فوراً عبر حسابه الفيزيائي المباشر دون المرور على ما قبله.

int x = arr[2]; // قراءة العنصر في الفهرس 2 بتعقيد O(1) arr[2] = 88; // تعديل القيمة في خطوة واحدة ثابتة O(1)
3.2 المرور وحساب المجموع والمتوسط (Sum & Average) التعقيد الزمني: O(n) · المكاني: O(1)

نستخدم متغيراً مجمعاً sum = 0، ثم نمر بحلقة واحدة على جميع العناصر ونجمعها، وفي النهاية نقسم على arr.length.

int sum = 0; for (int i = 0; i < arr.length; i++) { sum += arr[i]; } double avg = (double) sum / arr.length;
3.3 البحث الخطي (Linear Search) أفضل حالة: O(1) · أسوأ حالة: O(n)

نفحص العناصر عنصراً تلو الآخر من البداية حتى نجد القيمة المطلوبة فنخرج فوراً بـ break، أو تنتهي المصفوفة فنرجع -1.

int target = 25, foundIndex = -1; for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { foundIndex = i; break; // وجدنا القيمة، نخرج فوراً } }
أفضل حالة (Best Case): O(1)
عندما يكون العنصر في الخانة الأولى arr[0].
أسوأ حالة (Worst Case): O(n)
عندما يكون العنصر في آخر خانة أو غير موجود إطلاقاً.
3.4 إيجاد أكبر وأصغر قيمة (Min & Max) التعقيد الزمني: O(n) · المكاني: O(1)

نفترض أن أول عنصر arr[0] هو الأكبر والأصغر مبدئياً، ثم نمر في حلقة واحدة من الفهرس 1 لتحديثهما:

int max = arr[0], min = arr[0]; for (int i = 1; i < arr.length; i++) { if (arr[i] > max) max = arr[i]; if (arr[i] < min) min = arr[i]; }
3.5 عكس المصفوفة مكانياً (In-Place Reverse) المكاني: O(1) · الزمني: O(n)

نستخدم مؤشرين (Two Pointers): left = 0 و right = length - 1 ونبدل بينهما بمتغير وسيط temp دون إنشاء مصفوفة ثانية:

int left = 0, right = arr.length - 1; while (left < right) { int temp = arr[left]; arr[left] = arr[right]; arr[right] = temp; left++; right--; }

4. العمليات الهيكلية: الإضافة والحذف بالتفصيل

لماذا الإضافة والحذف يتطلبان O(n) زمناً ومكاناً في مصفوفات Java؟
لأن حجم المصفوفة ثابت تماماً (Fixed Size) في الذاكرة الفيزيائية. لا يمكن توسيع الخانات في مكانها ولا تقليصها، لذا لا بد من: حجز مصفوفة جديدة بالكامل ونقل العناصر إليها مع إزاحة المواقع.
4.1 عملية الإضافة في موقع محدد (Insertion at Position) التعقيد الزمني: O(n) · المكاني: O(n)

تتم الإضافة وفق 3 مراحل واضحة:

  1. المرحلة 1 (النسخ المباشر): حجز مصفوفة جديدة بحجم result[n + 1] ونسخ العناصر السابقة لموقع الإضافة (من الفهرس 0 إلى pos-1) كما هي.
  2. المرحلة 2 (غرس العنصر الجديد): وضع القيمة الجديدة في موقعها المخصص: result[pos] = val;
  3. المرحلة 3 (الإزاحة لليمين): نسخ ما تبقى من العناصر ونقل كل عنصر إلى result[i + 1] (إزاحة خانة واحدة لليمين).
مخطط إزاحة الذاكرة أثناء الإضافة:
10
[0]
99 (جديد)
[1] (pos)
20 (مُزاح)
[2]
30 (مُزاح)
[3]
40 (مُزاح)
[4]
public static int[] insert(int[] arr, int pos, int val) { // 1. حجز مصفوفة جديدة أطول بخانة واحدة int[] result = new int[arr.length + 1]; // 2. نسخ العناصر السابقة لموقع الإضافة كما هي for (int i = 0; i < pos; i++) { result[i] = arr[i]; } // 3. وضع القيمة الجديدة في مكانها المخصص result[pos] = val; // 4. نسخ العناصر اللاحقة مع إزاحتها لليمين (+1) for (int i = pos; i < arr.length; i++) { result[i + 1] = arr[i]; } return result; // إرجاع المصفوفة الجديدة }
4.2 عملية الحذف من موقع محدد (Deletion at Position) التعقيد الزمني: O(n) · المكاني: O(n)

يتم الحذف وفق 3 مراحل واضحة:

  1. المرحلة 1 (النسخ المباشر): حجز مصفوفة جديدة بحجم result[n - 1] ونسخ العناصر السابقة لموقع الحذف (من 0 إلى pos-1) كما هي.
  2. المرحلة 2 (التخطي): تخطي العنصر المحذوف arr[pos] تماماً وعدم نسخه للمصفوفة الجديدة.
  3. المرحلة 3 (الإزاحة لليسار): نسخ بقية العناصر ونقل كل منها إلى result[i - 1] لملء الفراغ.
مخطط سحب العناصر لملء الفراغ أثناء الحذف:
10
[0]
20
[1]
30 (حُذف)
[2] (pos)
40 ← يسار
[2] بدلاً من [3]
50 ← يسار
[3] بدلاً من [4]
public static int[] delete(int[] arr, int pos) { // 1. حجز مصفوفة جديدة أصغر بخانة واحدة int[] result = new int[arr.length - 1]; // 2. نسخ العناصر السابقة لموقع الحذف كما هي for (int i = 0; i < pos; i++) { result[i] = arr[i]; } // 3. نسخ العناصر اللاحقة مع إزاحتها لليسار خانة (-1) لملء الفراغ for (int i = pos + 1; i < arr.length; i++) { result[i - 1] = arr[i]; } return result; // إرجاع المصفوفة بعد الحذف }

5. مرجع الأكواد الأساسية الجاهزة (CRUD Operations)

برنامج Java متكامل يجمع الدوال الأربع الرئيسية (إضافة، تعديل، حذف، بحث) مع دالة main توضح كيفية استدعائها بالتسلسل:

/** * مختبر هياكل البيانات والخوارزميات (Data Structures Lab) * إعداد وتطوير: م. عبدالحميد هلال دعبان (بكالوريوس علوم حاسوب) * موضوع المعمل: العمليات الأساسية على المصفوفات الأحادية (Array CRUD & Analysis) */ public class ArrayCRUD { // 1. الإضافة: حجز مصفوفة جديدة وإزاحة العناصر لليمين O(n) public static int[] insert(int[] arr, int pos, int val) { int[] res = new int[arr.length + 1]; for (int i = 0; i < pos; i++) { res[i] = arr[i]; } res[pos] = val; for (int i = pos; i < arr.length; i++) { res[i + 1] = arr[i]; } return res; } // 2. التعديل: وصول مباشر وتغيير القيمة في خطوة واحدة O(1) public static void update(int[] arr, int index, int newVal) { if (index >= 0 && index < arr.length) { arr[index] = newVal; } } // 3. الحذف: حجز مصفوفة جديدة وإزاحة العناصر لليسار O(n) public static int[] delete(int[] arr, int pos) { int[] res = new int[arr.length - 1]; for (int i = 0; i < pos; i++) { res[i] = arr[i]; } for (int i = pos + 1; i < arr.length; i++) { res[i - 1] = arr[i]; } return res; } // 4. البحث: مقارنة تسلسلية خطوة بخطوة O(n) public static int search(int[] arr, int target) { for (int i = 0; i < arr.length; i++) { if (arr[i] == target) { return i; } } return -1; } // برنامج تجريبي لتشغيل العمليات: public static void main(String[] args) { int[] arr = {10, 20, 30, 40}; // أ. إضافة 99 في الموقع 1: arr = insert(arr, 1, 99); // النتيجة: {10, 99, 20, 30, 40} // ب. تعديل العنصر في الفهرس 0: update(arr, 0, 55); // النتيجة: {55, 99, 20, 30, 40} // ج. حذف العنصر في الموقع 2: arr = delete(arr, 2); // النتيجة: {55, 99, 30, 40} // د. البحث عن الرقم 30: int idx = search(arr, 30); // يرجع الفهرس 2 System.out.println("الموقع: " + idx); } }
