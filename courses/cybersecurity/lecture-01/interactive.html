1. المبادئ التأسيسية للأمن السيبراني والرياضيات المتقطعة للتشفير

مبدأ كيركهوفس الذهبي (Kerckhoffs's Principle)

«يجب أن يكون أمان النظام التشفيري مبنياً بالكامل على سرية المفتاح (Key)، وليس على سرية الخوارزمية (Algorithm).»
في علوم الحاسوب والسايبر، الخوارزميات (مثل AES, RSA, SHA-256) كلها خوارزميات مفتوحة المصدر ومنشورة عالمياً للتدقيق من قبل العلماء ومختبري الاختراق. الأمان الحقيقي هو في حجم وصعوبة تخمين المفتاح السري، وفكرة "الأمان عبر الإخفاء" (Security through Obscurity) هي وهم هندسي خطير.

مثلث الأمان CIA Triad

• السرية (Confidentiality): منع غير المصرح لهم من القراءة (التشفير المتماثل وغير المتماثل).
• السلامة (Integrity): ضمان عدم التلاعب بالبيانات (دوال الهاش SHA).
• الإتاحة (Availability): توافر النظام دون تعطل.

الحساب النمطي (Modular Arithmetic)

ساعة الأعداد الدائرية $\mathbb{Z}_m$: إذا تجاوز العدد قيمة $m$ نأخذ باقي القسمة فقط. هو أساس خوارزميات التشفير لأن العمليات الحسابية تظل محصورة داخل مدى محدد دون حدوث فيضان ذاكرة (Overflow).

عملية XOR ($\oplus$) السحرية

العمود الفقري لتشفير التدفق والكتل: $A \oplus B \oplus B = A$. إذا شفرنا النص بالمفتاح عبر XOR، فإن إعادة تطبيق XOR بالمفتاح نفسه تعيد النص الأصلي فوراً بسرعة فائقة في مسجلات المعالج.

مرجع الأكواد الأكاديمية (Java Security & Crypto Reference)

التطبيق البرمجي لمعايير التشفير الصناعية بلغة Java

أكواد نموذجية ومختبرة لطلبة السنة الثالثة باستخدام الحزم الرسمية javax.crypto و java.security، متوافقة مع أحدث إرشادات الأمن السيبراني الصادرة عن المعهد الوطني للمعايير والتقنية (NIST).

1. التشفير المتماثل: AES-256 بوضع GCM المعتمد للمصادقة

NIST Recommended / AEAD

يوفر وضع GCM التشفير والسرية مع مصادقة سلامة البيانات (Integrity) في آنٍ واحد ضد هجمات التعديل والتلاعب (Tampering):

import javax.crypto.Cipher; import javax.crypto.KeyGenerator; import javax.crypto.SecretKey; import javax.crypto.spec.GCMParameterSpec; import java.security.SecureRandom; import java.util.Base64; public class AESGCMExample { private static final int AES_KEY_SIZE = 256; // بت private static final int GCM_IV_LENGTH = 12; // بايت (96 بت موصى بها) private static final int GCM_TAG_LENGTH = 128; // بت public static byte[] encrypt(byte[] pText, SecretKey key, byte[] iv) throws Exception { Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding"); GCMParameterSpec spec = new GCMParameterSpec(GCM_TAG_LENGTH, iv); cipher.init(Cipher.ENCRYPT_MODE, key, spec); return cipher.doFinal(pText); } }

2. التشفير غير المتماثل: RSA-2048 مع حشوة OAEP

Asymmetric / OAEP Padding

توليد زوج المفاتيح (العام للتشفير والخاص لفك التشفير) مع منع هجمات التحليل الرياضي عبر حشوة OAEP العشوائية:

import java.security.KeyPair; import java.security.KeyPairGenerator; import javax.crypto.Cipher; public class RSAExample { public static KeyPair generateRSAKeyPair() throws Exception { KeyPairGenerator generator = KeyPairGenerator.getInstance("RSA"); generator.initialize(2048); // مفتاح بطول 2048 بت آمن حالياً return generator.generateKeyPair(); } }

نظام RSA تشفير غير متماثل (Asymmetric) 2048 - 4096 بت تبادل المفاتيح والتوقيع الرقمي التحليل إلى عوامل أولية والحواسيب الكمومية (Shor) آمن حالياً (2048+) / يجري التحول للـ PQC
بروتوكول Diffie-Hellman تبادل مفاتيح 2048 بت / ECC 256 الاتفاق على مفتاح سري عبر وسيط عام غير آمن هجوم رجل في المنتصف (Man-in-the-Middle) بدون توقيع أساس بروتوكول TLS 1.3 والـ HTTPS
دوال الهاش (SHA-256) دالة اتجاه واحد (Hash) لا يوجد مفتاح (بصمة 256) سلامة البيانات (Integrity) وعدم التلاعب هجمات التصادم (Collision) وهجمات أعياد الميلاد معيار الصناعة العالمي والبلوكشين
خلاصة الأمن السيبراني: في الأنظمة الحقيقية والحديثة (مثل HTTPS، SSH، و Signal)، لا نستخدم خوارزمية واحدة بمفردها؛ بل ندمج التشفير الهجين (Hybrid Cryptography): نستخدم RSA أو Diffie-Hellman لتبادل المفاتيح، ثم نستخدم AES فائق السرعة لتشفير تدفق البيانات، مع SHA-256 والتوقيع الرقمي لضمان السلامة وإثبات الهوية.

5. بطاقات المراجعة الذكية والاختبار التفاعلي السريع

اختبر فهمك للمفاهيم الأساسية قبل الانتقال للتطبيق العملي، عبر بطاقات الفلاش التفاعلية والاختبار التقييمي المباشر:

بطاقات المراجعة الشفوية (حاول الإجابة ذهنياً أولاً):

س1: لماذا يعتبر مبدأ كيركهوفس (Kerckhoffs's Principle) حجر الزاوية في التشفير الحديث؟
الإجابة النموذجية: لأن خوارزميات التشفير (مثل AES و RSA) تكون منشورة ومفتوحة المصدر عالمياً لتدقيقها واختبارها. يرتكز الأمان بالكامل على سرية المفتاح (Key)، فإذا سُرقت الخوارزمية لا يخترق النظام، بينما الاعتماد على إخفاء الخوارزمية (Security through Obscurity) وهم خطير يسقط فور الهندسة العكسية.
س2: ما الفرق الجوهري في التطبيق بين التشفير المتماثل (AES) والتشفير غير المتماثل (RSA)؟
الإجابة النموذجية: يستخدم AES نفس المفتاح السري المشترك للتشفير وفك التشفير، ويتميز بسرعة معالجة هائلة تناسب البيانات الضخمة (Gigabytes). أما RSA فيستخدم زوج مفاتيح (عام للتشفير وخاص لفك التشفير)، وهو أبطأ بنحو 1000 مرة، لذا يُستخدم فقط في تبادل مفاتيح الجلسة أو التوقيع الرقمي (Hybrid Cryptography).
س3: ما هو أثر الانهيار الثلجي (Avalanche Effect) في دوال الهاش مثل SHA-256؟
الإجابة النموذجية: خاصية تشفيرية تعني أن أي تغيير طفيف في المدخلات (ولو كان بتاً واحداً فقط أو حرفاً صغيراً بدلاً من كبير) يؤدي إلى تغيير جذري وغير متوقع في أكثر من 50% من بتات الهاش الناتجة، مما يمنع المهاجم من التنبؤ بأي نمط بين الرسائل وبصماتها.
